# StateSet iCommerce Engine PRD (2026)

## Summary
StateSet iCommerce is an embedded commerce engine designed for AI agents. It provides a portable, deterministic, zero-config runtime that developers can embed directly in applications and agents. This PRD defines the 2026 product scope for the iCommerce path.

## Background
Current commerce platforms are human-first, cloud-hosted, and rate-limited. AI agents need embedded, deterministic commerce primitives and structured data access without OAuth friction or network latency. iCommerce supplies the local-first commerce runtime and integrates with ACP for standardized agentic checkout.

## Problem Statement
- Agent builders cannot reliably transact using human-centric commerce APIs.
- Commerce state is locked in vendor clouds and is difficult to reason about.
- Deterministic, offline-capable commerce primitives are missing for agents.

## Goals (2026)
- Ship a production-grade embedded commerce engine with stable APIs.
- Publish and maintain bindings for 11 languages with consistent DX.
- Support deterministic commerce workflows (orders, inventory, payments, returns).
- Provide ACP-compatible integrations for agentic checkout.
- Drive developer adoption (open source) and convert Pro and Enterprise users.

## Non-Goals
- Replacing merchant platforms (Shopify, ERP, CRM) in 2026.
- Building a consumer-facing marketplace.
- Running a general-purpose payments processor.

## Target Users

### Primary
- AI agent developers integrating commerce workflows.
- Platform engineers embedding commerce into products or edge deployments.

### Secondary
- Enterprise teams deploying internal commerce agents.
- Startups shipping commerce-enabled AI tools.

## Core Use Cases
- Embedded commerce in AI agents (support, returns, subscriptions).
- Local-first commerce for offline or edge deployments.
- Deterministic test environments and simulations.
- Embedded order, inventory, and payment primitives for agent frameworks.

## Product Scope (2026)

### Core Capabilities
- Orders, customers, products, inventory, payments, returns, shipments.
- Deterministic operations with event sourcing and auditability.
- SQLite default with Postgres option for hosted services.
- MCP tool suite for agent tooling.
- ACP integration for checkout sessions and delegated payments.

### Functional Requirements
1. Embedded initialization with zero external dependencies.
2. Complete CRUD for orders, customers, products, inventory, and returns.
3. Inventory reservations and confirmations for checkout.
4. Payment records and refund workflows.
5. Event emission for all state changes.
6. Sync and export for integration with external systems.
7. Language bindings parity across core APIs.
8. Stable schema migrations and versioning.

### Non-Functional Requirements
- Latency: <10ms p99 for core operations in embedded mode.
- Reliability: deterministic behavior with consistent event history.
- Portability: single-file state for local deployments.
- Security: local data encryption option; safe defaults.
- Compatibility: consistent API across bindings.
