# x402 Payment Protocol

The x402 protocol enables cryptographically signed payment intents for agent-to-agent transactions. Payment intents are created off-chain with Ed25519 signatures and can be batch-settled on-chain.

## How It Works

```
Agent A                    Sequencer                     Chain
   │                          │                            │
   │─ 1. Create intent ──────►│                            │
   │   (Ed25519 signed)       │                            │
   │                          │                            │
   │◄─ 2. Intent ID ─────────│                            │
   │                          │                            │
   │─ 3. x402Fetch() ────────►│                            │
   │   (intent in header)     │                            │
   │                          │                            │
   │◄─ 4. Service response ──│                            │
   │                          │                            │
   │                          │─ 5. Batch settle ─────────►│
   │                          │   (periodic)               │
   │                          │                            │
   │                          │◄─ 6. Settlement receipt ──│
```

## Creating a Payment Intent

```javascript
const intent = await toolkit.executeTool('x402_create_payment_intent', {
    fromAgent: 'research-agent',
    toAgent: 'data-agent',
    amount: 0.02,
    currency: 'USD',
    description: 'Market data API call'
});
// → { intentId: '...', signature: '...', status: 'signed' }
```

## x402Fetch — Pay-Per-Request

Attach payment intents to HTTP requests:

```javascript
import { x402Fetch } from '@stateset/cli/x402';

const response = await x402Fetch('https://data-agent.example.com/api/prices', {
    agent: myAgent,
    maxAmount: 0.02,
    currency: 'USD'
});
// Payment intent automatically attached as x-402-payment header
```

## Budget Governance

Prevent agents from overspending with daily budget caps:

```javascript
const budget = await toolkit.executeTool('x402_budget_status', {});
// → { budget: { spentToday: 2.34, dailyBudget: 5.00, perCallLimit: 0.50 } }
```

When the budget is exhausted, further payment attempts throw `BudgetExceededError` — the agent stops spending rather than silently overspending.

## Circuit Breaker

The x402 client includes a circuit breaker for sequencer resilience:

```
Closed ──[failures exceed threshold]──► Open
                                          │
                                     [timeout]
                                          │
                                          ▼
                                      Half-Open
                                          │
                                    [success] → Closed
                                    [failure] → Open
```

- **Closed**: Normal operation, requests go to the primary sequencer
- **Open**: Requests are queued in an offline buffer; a fallback sequencer is tried
- **Half-Open**: A probe request is sent to check if the primary is healthy

## Signing Flow

Payment intents are signed using a deterministic process:

```
1. Construct intent JSON payload
   { from, to, amount, currency, nonce, timestamp }

2. Canonicalize (RFC 8785 JCS)
   Deterministic key ordering, whitespace removal

3. Domain-separated hash
   SHA-256("VES_EVENTSIG_V1" || canonical_bytes)

4. Sign with Ed25519
   signature = Ed25519.sign(agent_private_key, hash)

5. Attach signature to intent
   { ...intent, signature: hex(signature) }
```

This ensures:
- **Determinism**: Same intent always produces the same canonical form and signature
- **Non-repudiation**: Only the holder of the private key can produce the signature
- **Replay protection**: Nonce per payer prevents replay attacks

## Gas Abstraction

Agents never need to hold gas tokens. Settlement uses gas abstraction:

- **EVM chains (Base, Ethereum, Arbitrum)**: ERC-4337 Paymasters pay gas on behalf of agents
- **SET Chain**: ssUSD is the native gas token, with sub-cent transaction costs
- **Solana**: Relayer network covers transaction fees, recovered via settlement fee (basis points)

The sequencer network is permissionless — any organization can run a sequencer node.

## Settlement

Payment intents progress through settlement states:

```
unsigned → signed → pending → settled
```

Intents are batch-settled by the sequencer on a periodic schedule. Settlement can occur on multiple chains:

| Chain | Gas Token | Settlement Fee | Finality |
|-------|-----------|---------------|----------|
| Base | ETH (abstracted) | ~0.1% | ~2 seconds |
| Ethereum | ETH (abstracted) | ~0.5% | ~12 seconds |
| Arbitrum | ETH (abstracted) | ~0.1% | ~1 second |
| Solana | SOL (abstracted) | ~0.05% | ~400ms |
| SET Chain | ssUSD (native) | ~0.01% | ~2 seconds |

## SSRF Protection

The x402 client validates sequencer URLs before connecting:

- Only `http:`, `https:`, `grpc:`, and `grpcs:` protocols allowed
- Localhost and private IP ranges are blocked
- Internal TLDs (`.local`, `.internal`) are rejected
